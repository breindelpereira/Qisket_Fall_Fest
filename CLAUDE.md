# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Qisket: a mobile-first quantum computing learning app (React 19 + TypeScript + Vite, wrapped for Android with Capacitor 7). Games and simulations run on custom in-repo TypeScript physics engines (no quantum library). `RULES.md` (mirrored in `.gemini/rules.md`) is the project rulebook; `Plan/Implementation_Plan.md` holds the roadmap, and `Plan/Parts_2_and_3_Build_Plan.md` is the detailed plan for the unbuilt Part 2 games and labs, the Part 3 practice and the tutor notes for both.

## Commands

```bash
npm run dev          # Vite dev server
npm run build        # tsc -b && vite build
npm run lint         # oxlint (config: .oxlintrc.json), not ESLint
npm test             # vitest run (node environment, globals enabled)
npx vitest run tests/circuit.test.ts            # single test file
npx vitest run -t "Bell"                        # single test by name
npm run cap:sync     # cap sync android (after build); cap:open / cap:run for Android Studio / device
npm run build && npx cap sync android   # then, in android/: ./gradlew assembleDebug  ->  android/app/build/outputs/apk/debug/app-debug.apk (install with adb install -r)
npm run tutor:index  # rebuild tutor/index.json from the lessons + tutor/notes (a test fails if it is stale)
npm run check:no-keys # fail if an API key or a server-only name is in dist/, the Android copy or the source
TUTOR_URL=<function address> npm run tutor:eval   # the 20-question set against the deployed tutor function
```

## Architecture

- `src/core/circuit/`: state-vector engine (`complex.ts`, `gates.ts`, `statevector.ts`, `bloch.ts`, re-exported via `index.ts`). Pure TS with no React or DOM, so it runs under Vitest in node. `sampleCounts` and `measureQubit` take an optional rng for deterministic tests.
- `src/core/optical/interferometer.ts`: single-photon two-path engine (beam splitter, phase shifter, blocker) built on the same complex/matrix helpers. `core/stabilizer/` from `RULES.md` does not exist yet and Module 7 does not need it: Qubit Surgeon and the Noise Lab use the state-vector engine on a four-qubit register (three data qubits and a helper). `EngineType` in `content/types.ts` still names all three.
- `src/core/games/`: pure game rules, kept out of the components so they are testable (`blochRunner.ts`, `photonEscape.ts`, `chsh.ts`, `gateDeck.ts`, `teleportRelay.ts`, `oracleDetective.ts`, `qubitSurgeon.ts`, `hypeCheck.ts`; all but the first three build on `core/labs`, and `hypeCheck.ts` is just a card deck with its scoring). Each game component only renders and wires state to these modules. Add new games this way, with a matching `tests/*.test.ts`.
- `src/core/labs/`: pure maths behind the labs, tested in `tests/labs.test.ts` (`interference.ts` Mach-Zehnder fringes and bomb test, `shots.ts` histogram and statistics, `circuitBuilder.ts` the Circuit Lab grid model and presets, `twoQubit.ts` concurrence and reduced Bloch vectors, `bell.ts` correlations and the CHSH value, `teleport.ts` the three-qubit protocol, `deutschJozsa.ts` oracles and the DJ circuit, `grover.ts` oracle and diffusion, `errorCorrection.ts` the three-qubit repetition code: encode alpha|000> + beta|111>, probes A/B/C that compare two data qubits through a helper qubit and never read the data, the syndrome table, why two flips fool it, and the failure rate 3p² − 2p³ and its n-qubit generalisation, tested in `tests/errorCorrection.test.ts` against the engine). Qubit 0 is the least significant bit, so bitstrings read q(n-1)..q0 like Qiskit.
- `src/content/`: typed content models (`types.ts`), the concept data (`concepts.ts`), and `validator.ts`, which validates records at runtime (e.g. honesty tags, prerequisites). Games, sims, lessons and quizzes link to concepts by id (`relatedGames`, `relatedSims`, `relatedLessons`).
- Learn content is hand-maintained TypeScript, taken from `Questions/Quantum Computing Course Content (clean).pdf` (the `.docx` next to it is the older, shorter draft; Part 3 equations were images, transcribed by hand). `lessonsPart1/2/3.ts` define lessons as blocks (paragraphs, bullets with optional `math`, notes) and `lessons.ts` aggregates them; `lessonText.ts` derives each lesson's plain-text `textNotes` (what the AI Tutor should retrieve from). `quizzes.ts` holds all 50 questions with a per-quiz id (`quiz_module_1`, `quiz_hardware`, `quiz_math`, ...); the right answers are spread across A to D (a test checks the spread, and pins each right answer by its text, so only the order of options may change), and `activities.ts` lists every planned game/lab (built or not) so lessons can link to them. A lesson's activities must also appear in its concept's `relatedGames`/`relatedSims` (tests enforce this).
- Lesson page order (`core/learn/flow.ts`, rendered by `LessonView`): play a game, watch the video, try the lab, then a practice game, then the notes and the quiz. Each activity has a `role` in the lesson data (`discover` before the video, `explore` after it, `apply` last; games default to discover, labs to explore) and a lesson may set `flow` to reorder the stages (module 5B puts the lab first). Stages with nothing openable are skipped, and unbuilt activities are listed under "Coming soon", so a module without its game yet starts with its video. The Aha line and the common mix-up are shown after the stages because they give the answer away. The first time a module that opens with a game or lab is visited, `LessonView` shows a start chooser instead of the page (`core/learn/start.ts`): play the game (or open the lab) first, watch the video first (moves the video to the front), or see the whole lesson. The choice is remembered per module in localStorage (`qisket_lesson_start_v1`), and any progress on the module also counts as started. Modules that already open with their video skip the chooser. When a game from a lesson is finished, `ProgressStore.subscribeCompletions` fires and `App` shows `AfterGameSheet` (once per game per visit): the next stage of that lesson, usually the video (the lesson page opens scrolled to it via `LearnView.focus`), then the lab, practice, and finally the quiz (`nextAfterActivity` in `core/learn/start.ts`). Opening a game from a lesson passes the lesson id along so the right lesson is used when a game belongs to several (Gate Deck).
- `src/core/learn/`: pure quiz grading (`quiz.ts`) and curriculum progress (`curriculum.ts`: module status, up-next, course %). A module with a quiz is done when the quiz is passed (70%: a 3-question quiz needs every answer right, 4 questions need 3, 5 need 4); one without a quiz is done when marked as read. Course progress counts quizzes only (the team's decision), and the home tiles show quizzes passed, modules done and games and labs tried.
- `src/components/learn/`: the Learn tab (`LearnTab` routes between home, part, lesson and quiz views). The current view lives in `App.tsx` state so it survives tab switches. Maths is drawn by `MathView` from the structured `MathExpr` type; there is no maths library. Videos load from `youtube-nocookie.com` only after a tap. `VideoCard` talks to the player over postMessage (`useYouTubePlayer` + `core/learn/video.ts`; no YouTube script is loaded). A reference with `startSeconds`/`endSeconds` plays only that segment: YouTube's controls are hidden (`controls=0`), a shield sits over the video, the app draws its own play/pause/skip-10s controls, a seek bar limited to the segment, speed (0.75x to 2x) and English captions (sent to the player as `setPlaybackRate` / `loadModule` + `setOption` over postMessage; speed and captions are remembered in localStorage under `qisket_video_prefs_v1`) and pauses just before the end so YouTube's end screen never shows. A reference without a segment keeps YouTube's normal controls. Every lesson in all three parts has at least one video (a test enforces it). Part 1's videos come from the course document; the Part 2, Part 3, module 3, module 5B and module 7 videos were found by searching YouTube and checking that each is embeddable, so they are not in `Questions/` and should be re-checked if a video disappears. If the player reports an error or never answers, or sits unstarted for 10 s, the card says so and promotes the plain "Watch on YouTube" link (which cannot stop at an end time). YouTube can refuse embeds inside app webviews (sign-in prompt, or error 153 when no referrer is sent); this was verified on desktop but not yet on Android.
- `src/components/games/`, `src/components/simulations/`: each game or lab is one self-contained component with inline styles. Labs use the same arcade frame as games plus `simulations/labKit.tsx` (slider, bar chart with a dashed prediction marker, maths box) and `labUtils.ts` (`useExplored(simId, conceptId)` records the lab as explored on the first real action). The Labs tab is a hub like the Games tab: add a lab to `SIMS` in `App.tsx`. `src/components/shared/HonestyTag.tsx` is the badge component.
- Every game uses the same look from `src/components/shared/Arcade.tsx` (frame, header, title, banner, modal) and `arcadeTheme.ts` (tokens, per-game accent `THEMES`, panel styles). Buttons are the global `.btn`/`.chip` classes in `src/index.css`. Build new games from these instead of hand-written styles.
- `src/App.tsx`: single-file shell with tab state (home/learn/games/sims), game/sim selection and the AI tutor drawer (`components/tutor/TutorDrawer.tsx`, always mounted so a chat survives closing it), with no router. A new game or sim has to be imported and wired in here.
- `src/hooks/useProgress.ts` + `src/utils/progressStore.ts`: progress (completed games, explored sims, quiz scores per quiz id, lessons marked read, concept mastery tiers `locked/familiar/explored/mastered`) persisted to localStorage under `qisket_progress_v1`, with an in-memory fallback so it works under node tests. Mastery needs game/lab evidence (Mastered = quiz passed at the 70% mark and a lab run), so passing a quiz alone does not move the tiers.
- `src/utils/audio.ts`: sound helpers.
- AI Tutor (`src/core/tutor/`, `tutor/`, `worker/`): the app asks a small Cloudflare Worker (`worker/index.ts`, settings in `worker/wrangler.toml`, steps in `worker/README.md`) that holds the Gemini key; the app only knows `VITE_TUTOR_URL`. `server.ts` is the function's logic with no hosting details (request checks and limits in `guards.ts`, the model call in `gemini.ts`, the prompt and the "[P1]" source tags in `prompt.ts`); the Worker is only routes, CORS and settings. The knowledge is `tutor/index.json`, generated by `scripts/build-tutor-index.ts` from every lesson's own text (split into passages) plus the hand-written `tutor/notes/<lessonId>.md` (format in `tutor/README.md`); quizzes are never included. `search.ts` is BM25 keyword search shared by the app, the Worker and the tests, and it only returns passages up to the learner's position in the course (`position.ts`: the open lesson, the next one to do, or anything already started), so later modules are not spoiled; the course map is always sent so the tutor can say which module covers something later (`laterTopic` in `offline.ts`, used for the offline answer and, when nothing at all matches, by the function without calling the model; when something matches even weakly the model decides). Answer order in `client.ts`: small talk is answered on the spot; then the online tutor if the learner allowed it (`qisket_tutor_consent_v1`); if that is off or fails, a pre-written answer from `tutor/demo-answers.json` for the questions we expect (so a demo works without a network), else `offlineAnswer` from the notes on the device. The function retries a busy or slow model up to twice (once for a rate limit), trips a breaker (10 s after a hiccup, 60 s after a quota or key error), then tells the app to answer offline with a `detail` saying why (also logged: `npx wrangler tail --config worker/wrangler.toml`). The Worker is pinned near Google's US region with `[placement] region` in `wrangler.toml`, because Google answers `400 User location is not supported` to Gemini calls that leave from some Cloudflare data centres (found by running `npm run tutor:eval` against the deployed Worker); check the `Cf-Placement: remote-IAD` response header of `/api/health` to confirm it took effect (the `entry` field in the body is only where the request came in). Greetings and thanks are answered in the app without any lookup (`isSmallTalk`), and `http://localhost` on any port may call the Worker (`isOriginAllowed` in `guards.ts`). Learners can keep answers: "Save answer" under a tutor reply stores that question and answer, "Save chat" stores the whole conversation (saving a chat again updates the saved copy), and a "Saved" view lists, expands and deletes them (two taps). Every chat is also kept automatically in a History tab (the last 20, `qisket_tutor_history_v1`), so an answer from an earlier chat, or from before the app was closed, can still be opened and saved; "New chat" starts a fresh one without losing the last. The logic is `core/tutor/saved.ts` (tested in `tests/tutorSaved.test.ts`), kept on the device only in localStorage under `qisket_tutor_saved_v1` (at most 50 items); a full list or a blocked browser is reported instead of silently failing. Game-aware tutor: while a game is open (or was left in the last 20 minutes) the tutor is told about it. Each game calls `useActivityReport` (`hooks/useActivityReport.ts`, store in `core/tutor/activityStore.ts`) with a short description of its screen (level, mission, what the learner has done, the game's own hint, never the solution); the drawer reads it, shows a "Game: ... sharing ON/OFF" switch, and sends it as `activity` in the request (checked in `guards.ts` `parseActivity`, dropped quietly if unknown, not sent in a quiz). Labs work the same way: `content/labHelp.ts` has the same shape (the first section is `How do I use`, the last is `What should I notice in`, and there is no stuck nudge, because a lab has nothing to solve), the ten labs call `useActivityReport` too, and the prompt says `LAB CONTEXT` and tells the model to explain directly. What each game is and its common doubts is written in `content/gameHelp.ts` (one `How do I play` section first, an `I'm stuck` nudge, and a `What does finishing` section per game; a test checks the tag matches the game card and that the Hint-button texts are not repeated) and becomes passages with `activityId` in `tutor/index.json`. Those passages are searched only for the open game and ignore the learner's position in the course; `game.ts` adds the game's how-to passage to a question with no topic words ("I'm stuck", "what do I do now", which would otherwise pass for small talk), `prompt.ts` adds a GAME CONTEXT block that tells the model to nudge and not solve while playing, and the offline answer appends the game's hint for a learner who is stuck. "Ask about this": lecture-note paragraphs, labelled points and equations, the key idea, the common mix-up and every quiz question have an `AskButton` that opens the tutor with that part's plain text as `focus` in the request (`parseFocus` in `guards.ts`, helpers in `focus.ts`; the quiz sends only the question, never its options or answer). The text is added to the search and to the prompt, so "explain this" works, and the drawer shows an "Asking about" chip the learner can clear; the focus is forgotten when the drawer closes. Model names are never hard-coded in the app: `TUTOR_MODEL` is a Worker setting (default `gemini-3.5-flash-lite`), temperature is left at Google's default for Gemini 3, and `maxOutputTokens` includes thinking tokens. Files the Worker bundles import each other with `.ts` extensions and must not import the app's code; `tsconfig.tools.json` type-checks `worker/` and `scripts/` (run with `tsx`). It is deployed on the team's Cloudflare account (its address is the built-in default in `TutorDrawer.tsx`, so clones and hosted builds get the online tutor; `VITE_TUTOR_URL` overrides it, and an empty value means offline only) and no backup model is built (see the plan). `tests/tutor.test.ts` covers all of it with a pretend Gemini.

## Android build notes

- Needs `android/local.properties` with `sdk.dir=...` (git ignores it) and a JDK 17 or 21; Android Studio's bundled JDK (`<Android Studio>/jbr`) works. Put `VITE_TUTOR_URL` in `.env.local` before `npm run build` so the app has the online tutor, then run `npm run check:no-keys` after `cap sync` (it also scans the Android copy of the web files).
- Android 15 and later draw apps under the status bar and navigation buttons, and the keyboard would cover the bottom of the page. `capacitor.config.ts` sets `adjustMarginsForEdgeToEdge: 'force'`, and `MainActivity.java` replaces Capacitor's inset listener with one that also lifts the page above the keyboard (Capacitor 7 ignores the keyboard there). The dark purple behind the bars is `@color/appBackground`. Capacitor 8 is expected to make this the default.
- On some Windows machines Gradle fails with "Unable to establish loopback connection" (Java's internal socket file cannot be created). Workaround that worked: `JAVA_TOOL_OPTIONS="-Djava.net.preferIPv4Stack=true -Djdk.net.unixdomain.tmpdir=<a short existing folder without spaces>"`.
- Full-screen lesson video hides the status bar and navigation buttons through a small plugin of our own, `ImmersivePlugin.java` (registered in `MainActivity` before `super.onCreate`; the page calls it from `src/utils/immersive.ts`, which does nothing in a browser). A swipe from the screen edge shows the bars for a moment. It also turns the phone to landscape and lets the page use the notch area while a video is full screen, then restores both. Verified on a real phone (Android, with a camera cutout).
- The app has the INTERNET permission only. The tutor function allows the app's origin `https://localhost` (see `worker/wrangler.toml`).

## Project rules (from RULES.md)

- **Never change test expectations to make tests pass.** Fix the code or algorithm instead. Tests encode textbook physics (HXH = Z, Bell state 50/50 with perfect correlation, state-vector normalization, etc.).
- **Every game, simulation and model must visibly show an Honesty Tag**: `Analogy`, `Simplified model`, `Accurate`, or `Experimental/Contested`.
- Mobile-first: touch targets of at least 44×44px, colorblind-safe (never color alone), and an untimed mode for any timed gameplay.
- AI Tutor: answers only from approved product content, and API keys must never live in client code (serverless proxy).
